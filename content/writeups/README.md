## Add a writeup

1. Create `content/writeups/<competition>-<challenge>/README.md` using `TEMPLATE.md` as a guide. Keep screenshots and solution files alongside it.
2. Add its metadata to `catalog.json`: a unique stable slug, competition, category, summary, tags, skills, source path, `format: "markdown"`, and estimated reading minutes. Leave unknown dates, points, and solve counts as `null`; do not infer them.
3. Keep downloadable files in the casefile folder. The build publishes Markdown casefile folders automatically under `/writeup-files/<slug>/`.
4. Run `npm test`, `npm run lint`, `npm run typecheck`, and `npm run build`. The build creates the reading pages automatically.
5. Publish through the portfolio repository. Changes in the former standalone repository are not automatically synchronized.

Do not replace the preserved archived HTML or the imported historical evidence when editing the reading version. The preservation tests protect those original files.

## Remaining evidence

The Will still needs the original executable or download link, its hash, and verified resource boundaries for full reproduction. Its published screenshot and original solver are retained, but no new verification or solve result is claimed.
